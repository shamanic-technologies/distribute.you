## Source-substring guards (dashboard/admin/landing tests alike)

Many tests assert a source file contains/omits a literal. They pass on code that does not run and fail on correct code. Rules, each cost at least one wasted CI cycle:
- **Comments trip guards.** A `not.toContain/not.toMatch` fails on your own explanatory comment; reword it, or assert against a comment-stripped copy (`stripComments(src)`). Before adding a `not.toContain("<literal>")`, grep the WHOLE target file for the literal. Some guards scan all of `src/` for a co-occurrence (`api-proxy.test.ts`: `getToken` + `apiCall`), so a doc comment in a file you never opened can trip them: read the guard's predicate. The repo-wide vocabulary guard (`one-word-for-a-sales-funnel.test.ts`) bans a word built as `["ch","ain"].join("")` and scans `src`, `tests`, `public`, `scripts` of ALL apps (tests/comments included); read its `BANNED` construction first, do not guess the word. `tests/no-sales-funnel.test.ts` also bans `funnel` (identifiers included) in `apps/dashboard/src` outside its wire-name allowlist.
- **If the literal is legitimate elsewhere, SCOPE the guard** to the function you changed, never file-wide.
- **Slice anchors**: `indexOf` takes the FIRST hit, so a doc comment naming the token mis-anchors the slice, and a hoisted/duplicated `const` moves it. Anchor on the function signature or a JSX-only/copy string. `sliceFrom` only looks FORWARD (anchor on the gate, assert the copy, not the reverse). Measure offsets (`python3 -c "s=open(f).read(); print(s.index(target)-s.index(anchor))"`); a negative number means wrong direction.
- **Slice bound depends on polarity.** `toContain`: bound to the NEXT declaration (`src.slice(at, src.indexOf("function <next>("))`), never a char count. `not.toContain`: measure to the function's closing brace, do not pad (a long slice reaches a neighbour's comment); write the measured number beside it. A block that begins with a comment cannot be bounded by `"\n  // "` (use `"\n\n"`). A JSX element cannot be bounded by `/>` (self-closing children carry it first); bound by the section that follows.
- **Counting/first-index guards assume one component per file.** Adding a sibling component breaks `match(...).length` and `indexOf("<thead>")` guards: bound every existing guard to its own component first.
- **Do not pin LAYOUT.** A multi-argument call's one-line form, or a literal spanning a formatter break (`setQueryData(["x"`), breaks on prettier reflow with no behaviour change: assert fragments that cannot split, each argument without trailing punctuation. **Never run a formatter (`prettier --write`) over a guarded file** (456 lines reflowed, 9 guards red in one run); restore with `git checkout origin/main -- <file>` and re-apply edits as scripted, asserted `replace`s.
- **Copy guards**: assert the SOURCE spelling (`&apos;`, not `'`); a guard slicing from `return (` counts JSX comments as copy (em-dash guards), so write JSX comments with colon/parens or above the `return`.
- **A guard pins CALL SITES, not only the component**: a prop/helper nothing passes or calls is the feature absent with the module perfect. Prefer INDEX COMPARES for declaration/ordering invariants (TDZ reads, setActive-before-push) since `toContain` cannot see order. A guard pinning where a hook may be CALLED goes stale when a second surface earns it: read its comment for the intent, widen the place, keep the invariant.
- **Alias-free modules get REAL unit tests** (vitest has no `@` alias): keep `lib/*.ts` helpers free of runtime `@/…` imports.
- **`hidden={cond}` loses to a display class** (`flex`/`grid`): conditionally RENDER, or put `hidden` in the className.

## Verifying rendered behaviour: REPRODUCE it

A source guard proves spelling, never behaviour. For an interaction or layout bug, reproduce headlessly (Playwright is a devDependency of `apps/dashboard` and `apps/admin` only; use `@playwright/test`, and keep the script INSIDE the app dir; landing checks run from the dashboard dir). Put the OLD and NEW markup on one throwaway page and assert they differ.
- Touch: `devices['Pixel 7']`, record the event sequence (`mouseenter, click`). Throwaway HTML needs `<meta name="viewport">` or the "390px" run is a 980px layout (tell: an element's x beyond the viewport, or `innerWidth` growing).
- Classes need COMPILING: build CSS through `@tailwindcss/postcss` with an entry file INSIDE `apps/<app>` (`@import "./src/app/globals.css"; @source "<abs path in /tmp>";`). Bare `@import "tailwindcss"` drops `@theme` tokens and the `html.dark` remaps (CSS ~14KB vs ~148KB is the tell). `postcss` is not a direct dep: import it from `node_modules/.pnpm/postcss@<v>/...` (path includes the workspace dir).
- Brand tint probes: `.tone-tile` reads `--brand-hue-delta`; the `brand-*` ramp reads `--brand-hue` under `data-brand-tint`. Set the right one and check at least one layer moved.
- Module constants into a probe: write a throwaway VITEST that `writeFileSync`s the real value. esbuild: use the versioned `.pnpm/esbuild@<v>/node_modules/esbuild/bin/esbuild` as an executable (no `node` in front). Bundling a page-level component needs stubs for `next/navigation`/`next/link` (loop on esbuild's missing-export errors), node builtins STUBBED to an empty module via a plugin (`node:crypto` from `anon-session-token.ts` fails `--external` with `Dynamic require ... not supported`), `window.process={env:{NODE_ENV:"development"}}` in the HTML, and a `pageerror` listener (a blank probe without one reads as "rendered nothing"). Screenshot from a plain `node` script with `chromium.launch()`: `npx playwright test` boots the app's `webServer` and times out. Render a hook-free body component (`CampaignBody({path})`) over a fixture, or stub `@/lib/api` with a module that `export * from` the real one and redefines only the calls the flow makes (a module's own exports shadow `export *`; esbuild `onResolve` plugin), its fake server in localStorage so a reload test sees what the server holds. Stub `useAuthQuery` with a REAL `useQuery` over the fixture (a plain-return stub ignores `setQueryData`, so a save looks lost).
- Wait before measuring: animated counts, CSS transitions (`getComputedStyle` returns the interpolated value), recharts bar animation. Assert the final value programmatically before screenshotting.
- `max-h-full` pins nothing under an indefinite-height parent (clips both ends; measure the header's `top`, a negative value proves overflow): use viewport units or make the parent definite. Measure tables with `scrollWidth` vs `clientWidth` on the wrapper, old markup beside new.
- Ship probe scripts to the box as base64 (`base64 -i f | tr -d '\n'`), never as an unsubstituted placeholder in a nested heredoc.

## Release flow (distribute.you specifics)

No `release.sh hotfix` here (that is for backend semver services). The Hetzner box (`/root/distribute` on `167.233.196.79`, key `~/.ssh/oracle-distribute`, user `root`; config mirrored in `shamanic-technologies/distribute-box`) pulls `main` and rebuilds unattended within ~7 minutes of a merge: no tag, no bump, nothing to promote. **Nothing is on Vercel** (landing + dashboard cut over 2026-08-09; `vercel.json` files and `scripts/vercel-ignore.sh` are vestigial; there are NO preview URLs, verify by reproducing or on prod after merge). A merged backend PR is not in production until the box rebuilt it: the discriminator is behaviour or the served artifact, never PR state.

**Deploy mechanics.**
- Each service has its own clone `repos/<service>`; `deploy.sh <service>|--all|--status` does fetch, `reset --hard origin/main`, `compose build`, `up -d`, an in-container `/health` check, and **rolls back the clone when health fails** (build failure never touches the running container). `deploy-cron.sh` runs `--all` every 5 min under `flock` (a PULL from the box on purpose: no machine key in GitHub secrets).
- **`deploy-admin.sh` is a one-line wrapper around `./deploy.sh admin-app --force`.** The three Next apps (`landing-app dashboard-app admin-app`) deploy as ONE group off one shared clone and ride the 5-min cron: a merge reaches `admin.distribute.you` unattended (a note claiming otherwise was wrong). `--force` exists ONLY for the apps (rebuild after a `NEXT_PUBLIC_*` change, which is inlined at build from `env/<app>.build.env`); never for a backend service.
- **`deploy.sh` takes the deploy lock itself** (`take_deploy_lock`; hand-runs wait up to 30 min, the cron skips; `--status` exempt; the cron exports `DISTRIBUTE_DEPLOY_LOCKED=1` so a child does not block on its own parent).
- **`fetch_main` retries 5x and FAILS LOUD**: a failed fetch used to read as `already on <sha>, nothing to do` (GitHub intermittently 401s unauthenticated fetches). `git-credential-distribute` supplies the PAT from `env/admin-app.env` `GITHUB_CONFIG_TOKEN` (prefers `env/github-deploy.env` `GITHUB_DEPLOY_TOKEN` if present).
- **Service list flake**: `compose_services()` retries 3x, caches per run, fails loud (before, `docker compose config --services` flaking silently skipped services with no log line; tell = ABSENCE of a `<service>:` line). `deploy-watchdog.sh` condition 3 now catches a clone behind `origin/main` on two consecutive runs.
- **Waiting for your fix**: match the MERGE commit or a content marker, never the PR branch sha. A marker must be a code construct, not a literal your own comment can contain. For a Next app grep `.next/static` + `.next/server` (never all of `/app`), and read the merge subject with `git log` (squash makes `--is-ancestor` lie). Gate any outcome probe on `deploy.log` showing `healthy on <a sha that CONTAINS your merge>` (the log names the group HEAD; a later merge in the same tick hides yours, so grep the content marker, not your sha). Pair with the global rules on stale clones, buffered `deploy.log`, `--force-recreate`, hand-builds under the lock.
- **An app deploy is a hard 502 while the new Next server binds**: every vhost proxying an app carries Caddy `lb_try_duration 30s` + `lb_try_interval 500ms` (retries only failed DIALS, so write-safe; never retry on status codes). Add it to any new app vhost; do not remove it. Verify against the RUNNING config (`wget -qO- http://localhost:2019/config/ | grep try_duration`, six hits), not the file. It bounds the outage, it does not remove it (requests over 30s still break).
- **The Caddyfile is bind-mounted as ONE FILE**: edit by truncating in place (`cat > Caddyfile`), never `sed -i`/`mv` (new inode, container keeps the old file; `caddy validate` and `reload` still report success). Confirm with `ls -i` before/after and `docker compose exec -T caddy grep -c <marker> /etc/caddy/Caddyfile`; a diverged inode needs `docker compose restart caddy` (~5s blip).
- **Self-hosted Next does not inherit from Vercel**: `export const maxDuration` does nothing (the only ceiling is Caddy's `read_timeout 310s`; streaming routes need `flush_interval -1`); `request.url` in a route handler is the BIND address (`http://0.0.0.0:3000`), so emit a RELATIVE `Location` for redirects (`new NextResponse(null, {status: 308, headers: {Location: "/#how"}})`); the landing prerenders `/blog` and `/sitemap.xml` from `DATABASE_URL`, passed to the build as a BuildKit secret (never a build arg), and a build without it silently yields an empty blog. Before retiring any platform, pull out the secrets only it holds (`NEXT_PUBLIC_*` can be read off the live bundle).
- **Backups fail PER DATABASE** (`pg_dump` as the service role aborts on the first unreadable table; a table made as `postgres` blocks that database's backup while the run still reports `N ok, M failed` in `/var/log/pg-backup.log`). Fix with `GRANT SELECT` + `ALTER DEFAULT PRIVILEGES`, never `DROP`; prefer temp tables for ad-hoc work. A hung `docker compose run --rm` job survives `--rm` (`docker ps` shows `Up 2 weeks`): compare container age with the cron interval.
- **Watchdogs, each its own cron entry because they fail independently**: `deploy-watchdog.sh` (`*/15`, pipeline: no tick in 20 min, `git fetch failed`/`BUILD FAILED`/`unknown service`/`UNHEALTHY` in a completed tick, clone behind origin twice) and `health-watchdog.sh` (`*/5`, fleet: each service's own `/health` from inside its container, 3000 `/api/public/health` for Next apps, alert after TWO failures, mail a recovery, restarts nothing). `typesafe-watchdog.sh` (`20 */6`) is a SYNTHETIC probe of the Jev chain through chat-service `/internal/platform-judgments` (real traffic is ~1 reply/month so a failure RATE would read healthy); TypeSafe publishes no balance endpoint, so it alerts on the chain being broken and its mail carries the raw response. All mail via Postmark off `env/dashboard-app.env`, dedup per hour, silent while the deploy lock is held, and record their own send's HTTP code. A `flock -n 7 true` is the FILE form (always succeeds); use the fd form. Dry-run any watchdog in both directions before arming.

**Which host serves a domain** is answered by the response header (`via: 1.1 Caddy` = the Hetzner box), never by a vendor CLI or env var. **What a component does** is answered by its ACTIVITY (jobs run, rows written), never by its config: Railway env still pointed `*_SERVICE_URL` at `railway.internal` peers, and repointing Windmill at them would have woken a second execution engine (the real counts were 0 jobs/6h there vs 180 runs/30min on Hetzner).

**Branching and merge (Conductor).** Create a NEW workspace per task; do not `git checkout -b` manually. Branch prefix `KevinLourd/`.
- **Hotfix** or **additive prod-direct work**: branch from `origin/main`, PR to `main`, `gh pr merge --auto --squash`.
- **Bugfix / feature**: branch from `origin/staging`, PR to `staging`; promotion via `release.sh promote` (staging is a merge buffer that deploys nowhere).
- **`apps/dashboard/` + `apps/landing/` only**: PRs merge straight to `main` in practice (follow the last 5 merges on the file; when in doubt staging). Cross-cutting (`shared/`, `packages/`, multi-app) goes through staging. A NEW app under `apps/` or any edit to root `package.json`/`pnpm-lock.yaml`/`pnpm-workspace.yaml`/`turbo.json` prefers staging by blast-radius POLICY: `guard-branch.sh` only checks that the branch descends from `origin/main`, so main-direct is mechanically allowed and is right for an isolated change (e.g. deleting one self-contained app).
- **Copy-only `shared/content` is prod-direct-eligible** (`BRAND.tagline/hero` and content strings have no runtime JSX consumer; only `generate-readme.ts` reads them). A change to code/types/runtime exports there still goes through staging.
- **protect-main hook**: dashboard-to-main is allowed only while the branch descends from `origin/main`, and the local ref advances even without a fetch, so a green `--is-ancestor` a minute ago proves nothing. On `BLOCKED: Cannot create PR targeting protected branch 'main'`: `git merge origin/main --no-edit` (not rebase), re-push the same refspec, retry, and re-run the dashboard tests (you pulled others' guards).
- **`--auto` squash can stall `DIRTY`** when two PRs edit the same hot lines (feature lists); poll `gh pr view N --json mergeStateStatus`, treat `DIRTY`/long `BLOCKED` as an action signal, merge `origin/main` and keep BOTH sides.
- **Before REBUILDING an existing dashboard/admin PAGE**: `git fetch origin main && git log origin/main -20 -- <page dir>` first (a parallel rebuild, or its backend contract, may already be merged; adopt its typed readers and EXTEND them). Two workspaces editing the same files additively is not a conflict.
- **`release.sh promote` conflict here is usually BIDIRECTIONAL divergence** (dashboard/landing merge main-direct while staging carries its own backlog), not the release skill's clean-superset case. Recovery: merge main INTO staging (`git checkout -B sync/promote-resolve-vX origin/staging && git merge origin/main`), resolve per hunk by INTENT (keep HEAD toward the newer direction; never `git checkout --ours <file>`, it drops main's auto-merges), verify markers 0 + dashboard `tsc` + dangling imports, `git push origin sync/...:staging`, confirm `merge-base --is-ancestor origin/main origin/staging`, close the stale promote PR, re-run promote.

- **A cost per outcome at ZERO outcomes is `Learning`** (served `isMature: false`), never a floor and never total spend; do not re-add a `?? spend` fallback (it printed "Cost per positive reply $29" above "Total spent $29"). Net committed = `SUM(COALESCE(net_cost, total_cost)) FILTER (status IN ('actual','provisioned'))` (`net_cost_in_usd_cents` is NULL on pre-discount rows).
- **EVERY money reader sends `pricing=net`** (what the org pays; default is gross): `getBrandRevenue`, `fetchFeatureAudienceStats`, `getWorkflowProjectionLadder`, and server-side builders with no browser client (`outcome-digest.ts` built its own URL and published GROSS to an inbox while the page read net). Rule covers readers whose output is a COUNT (the forecast bar is budget divided by a gross divisor). `tests/projection-pricing-net.test.ts` is the inventory: add yours. - **A fleet-wide estimate is cross-org + BEST workflow (MIN over per-workflow ratios), never pooled across workflows** (features-service v0.106.1; pooled fleet $8.33 vs best ~$2.42 under one label). Both readers of one benchmark must ask the same `pricing` basis.
- **A REQUIRED query param on a per-day read is a 400 on every poll that reads as "nothing to show"**: pipeline-activity needs `timezone`. Send it from every caller, key the query on it, and guard the CALL SITES, since the reader declares it optional.
- **A cost-semantic delta is inverse**: a FALLING cost is green, a rising one red.
- **A brand's status is a COMPOSITE of two services**: paused lives in campaign-service (`brand_pause_transitions`: `brand_id`, `paused`, `transitioned_at`, take `DISTINCT ON (brand_id) … ORDER BY brand_id, transitioned_at DESC`), the budget in billing (`brand_funnel_daily_budgets`, `SUM(daily_budget_cents)`; `brand_daily_budgets` is EMPTY). The inverse: a primary table COLUMN is read straight off the row when the table's own feed serves it (check the openapi first; the Leads Audience column joined by email while `audience {id,name,avatarUrl}` was on the row).

**Wire shape (rot).**
- **Deployed openapi is ground truth.** Before declaring any typed helper/Zod schema for a backend endpoint, fetch the real shape via the `api-registry` MCP (live over source over a local clone). Never invent from a PR description. A registry ABSENCE is not proof a producer did not ship (refresh cadence): read the producer's served `openapi.json` from inside its container. An openapi param list for a passthrough route is a description, not its contract.
- **`apps/dashboard/src/lib/api.ts` and `apps/admin/src/lib/api.ts` share byte-equal readers and DRIFT**: migrate both in the same PR (stragglers bit in both directions, #2070, #2451). Prefer byte-equal; diverge only where a support type is absent.
- **`safeParse` every list/get wrapper** talking to an external service. Per-VERB schemas (a write DTO is narrower than its read). A too-narrow `z.object()` SILENTLY STRIPS new backend fields (add to Zod too). A not-yet-deployed ADDITIVE field is `.optional()` to decouple the rollout. A renamed field left `.nullish()` under its old name reads `undefined` forever (grep the old name; `new ?? old` only for a pure rename, never for two live concepts such as `committedCostUsd` vs `actualCostUsd`). `.optional()` rejects `null`: a producer's required-and-nullable field needs `.nullish()`. A schema written from a SAMPLE is a claim about the sample: parse the producer's WHOLE population through the real reader once before shipping. Numeric fields typed `integer` can arrive as strings (`z.coerce.number().nullable()`, no `??`/`.default()`; file a producer issue). A parser shared across grains must accept every grain's body (a subject field required at one grain is absent at another). A middle hop that re-declares a producer's enum rejects values the owner accepts: delete the copy, forward the field. A producer-computed VERDICT is READ, never re-graded from its inputs (the local grade is stricter than the producer's).
- **Data existing in a service does not mean the dashboard can reach it**: api-service (gateway) must proxy it. Probe with `api-registry` `call_api` on `/v1/<path>`: 404 `Not found` = route absent, 401 `Missing authentication` = present. The gateway RENAMES and sometimes drops prefixes (features `/public/stats/*` is `/v1/public/features/*`; crm `/orgs/contacts` is `/v1/orgs/contacts`; instantly `/orgs/conversations` is `/v1/conversations`), so probe both forms and conform to the deployed path. `GET /v1/leads` and the revenue proxy forward the query VERBATIM (a new filter needs no gateway PR); `/v1/features/brands/:id/offers` is the money read, `/v1/brands/:id/offers` the brand-service catalog.
- **An IDENTITY value a downstream needs rides a HEADER or the QUERY STRING**, never only the body: `buildInternalHeaders` promotes `brandId`/`campaignId`/`featureSlug`/`workflowSlug` from headers/query only. A body-only `brandId` reaches the third service with no `x-brand-id` and dies as a generic 502 (crm-service CSV upload #2968, GoHighLevel connect #4339). Put it in the query even when the body has it, and say why in a comment.
- **Bulk readers keyed by `?domains=a,b,…`/`?ids=` fail silently at scale** (URL size): CHUNK (200 keys, concurrency ~4), RETRY transient transport failures per chunk with backoff (a barrier that throws on one chunk empties the whole map), FILTER junk values first (`isQueryableDomain`; one `-` or path 400s its whole chunk), and GATE any export on the enrichment query settling. Nullable backend strings need `(x ?? "").toLowerCase()` in filters. Brand-level DR/traffic readers still exist in both apps and have diverged (dashboard is on the client fan-out, admin on server-side `?enrich=ahref`).
- **Free-form `variables`/`inputs` passthrough** (content-gen prompts): map payload keys 1:1 to the template's published `.variables` (`GET /v1/content/platform-prompts?type=`) or the model gets empty `{{…}}`; content-gen requires all declared vars non-empty, so add a new optional var as an extra passthrough key. An openapi `description`'s prose can lag the code: confirm against code/live and DB.
- Every authed Next app shell needs a route-segment `error.tsx`; `components/report/*` and anything in the no-login `src/app/report/**` bundle MUST NOT import `@/lib/api` (guarded by `tests/pr-expert-public-report.test.ts`).

**Boot registrars (dashboard and admin) write into shared stores.**
- **Email templates are keyed by `name` and last-writer-wins**; a template name has ONE owner, the app/service whose cron/route SENDS it (do not register it in a sibling "just in case"). The one-owner rule spans repos: `git grep '"<name>"' origin/main` in the backend senders (billing-service owns `credits-reload-failed` + `brand_daily_budget_changed`; this repo owns the six dunning templates). Verify a registration by reading the DESTINATION table (`email_templates` in transactional-email), not the code. Admin's digest surface was deleted for clobbering the dashboard's.
- **Platform keys**: `PLATFORM_KEYS` in each app's `src/instrumentation.ts` registers shared secrets into key-service (`POST /platform-keys` each cold start). A secret in a consumer's own env is a gap: add `{ provider, envVar }` in the app that holds the var. A missing env var only `console.warn`s (confirm presence on the box); the same provider from both apps is safe only while values are byte-equal; both `platform-config-startup.test.ts` pin the list AND an exact count.
- **A boot seed that upserts by NAME cannot express a RENAME** (old row survives; a unique-per-concept invariant can fail the boot, and on the box that is `UNHEALTHY … rolling back` with no cause in `deploy.log`). Prune rows absent from the seed in the SAME ship as a rename. `deploy.log`'s last line is not current state; read the clone HEAD + container health + the destination store.
- **A synthetic caller identity** (`x-external-user-id` for a job with no person: digest scan, no-login report proxy, share-link proxy) CREATES a user row, so key it on the JOB in the `system-` namespace (`lib/service-identity.ts`, byte-equal twins), never on the org (89 phantom rows vs 64 real users; the public `/investors` user count excludes only `system-%`). Guards: `tests/service-identity.test.ts` in both apps.

## No fallbacks: fail visibly

NEVER add fallback logic (`||` alternatives, silent defaults, graceful degradation) when data is missing/mismatched: `console.error` with value + context, and show an error UI for a missing required field. Exceptions: (1) Vercel-era build-time prerender (`sitemap.ts`, `generateStaticParams`, OG routes) prefer `try / console.error / continue empty` over a throw that aborts the build (the landing prerender still reads `DATABASE_URL`); (2) user-facing REASSURANCE surfaces (the campaign "Live activity" feed, `lib/campaign-activity.ts`) deliberately hide errors and show an allowlist of present-tense steps keyed on the event SLUG (owner: "on n'affiche pas d'erreur à l'utilisateur, on est là pour le rassurer"); do not "fix" it. A reload/skeleton/empty state must never stand in for a failure the user can act on.
