Key takeaway

An AI agent can now open a distribute.you account, get its own API key and pay, with no human in the loop.

  • 2 calls get a key: an email it can read, then the code it receives.
  • Free calls work at once. Paid calls are prepaid from $10, with automatic top-up.
  • No free credit and no trial: the agent pays before it spends.

Most APIs stop an AI agent at the first step. To get a key, someone has to open a browser, fill a signup form and type a card number. The agent can read the docs and write the code, then it waits for a person.

We removed that wait. An agent can now sign up for distribute.you, get an API key and prepay on its own. A person only steps in if the agent cannot pay by card itself.

How an agent gets a key

The agent gives an email address it can read and a phone number. We email it a 6-digit code.

curl -X POST https://api.distribute.you/v1/agent-signups/start \
  -H "Content-Type: application/json" \
  -d '{"email":"agent@example.com","phone":"+14155550100"}'

It reads the code in its inbox and trades it for a key:

curl -X POST https://api.distribute.you/v1/agent-signups/complete \
  -H "Content-Type: application/json" \
  -d '{"email":"agent@example.com","code":"123456"}'

The answer carries the key, sent as Authorization: Bearer <key> on every call after that. Each call to complete creates a new key, so an agent can make as many as it needs. The same email can later sign in to the dashboard, so the person behind the agent sees everything it did.

Why an email and a phone

Agents read email now, and many have their own address. The email is where we send account updates, so it has to be real: the code proves it. The phone is for urgent matters only, on WhatsApp. We check its format and nothing else.

There is no CAPTCHA and no limit on keys. A CAPTCHA blocks the exact caller we want to serve.

How an agent pays

Free calls work as soon as the key exists: brands, stats, the price catalog. Every paid call is paid upfront. No free credit, no trial. That is how we keep free riders out without blocking agents at the door.

curl -X POST https://api.distribute.you/v1/billing/accounts/prepaid_checkout \
  -H "Authorization: Bearer distrib.usr_..." \
  -H "Content-Type: application/json" \
  -d '{"topup_amount_cents":1000,"auto_topup_amount_cents":1500,"auto_topup_threshold_cents":500}'

The agent picks the amount: at least $10 to start. Automatic top-up is required, at least $15 each time the balance falls under $5 or more, so a campaign never stops halfway. The call returns a payment link. The agent opens it, or hands it to its human for one card entry.

What happens before it pays

A paid call with an empty balance answers 402 payment_required. The body says what to do: the prepay route, the minimums, and a note that a human may need to open the link. The agent does not have to guess why it failed or search the docs. It reads the error, prepays and retries.

The same flow runs through our MCP server and CLI. With the CLI it is distribute signup, then distribute signup verify, then distribute prepay --amount 10 --reload 15 --below 5. A payment-required error exits with code 8.
