- **`request.url` in a route handler is the request as ARRIVED**, not the rewritten one: slicing an internal prefix off it collapses short paths to `/`. `originPathFor` holds the rule (unit-tested).
- **The route serves raw bytes**: no token substitution, analytics or Organization JSON-LD rewrite; a guard asserts `staticResponse()` helpers are unreachable from it (explain history in the TEST, not the component).
- **Unset `CLONE_BASIC_AUTH` LOCKS (401), never opens.** `/robots.txt` on a clone host answers `Disallow: /` BEFORE the password. Host resolved against the CATALOGUE; traversal stopped twice (`clonePathFor` segment rejection + resolved-path containment).

- **Dockerfile needs an explicit `COPY` for `clones/` and `archives/`** (untraced by Next; container healthy, host 404s).
- **Capture is TWO passes**: `scripts/clone-site.mjs` (static, ASSET refs only, never document links) then `scripts/capture-live.mjs` (Chromium, 4 viewport/DPR combos, records real fetches; a cache-served response has no body: REFETCH). Next client-nav `?_rsc=<hash>` never matches a captured hash: answer an exact miss with ANY stored `_rsc` variant (`isRscCacheBusterOnly` / `pickRscVariant`).

## Copy and positioning invariants (public surfaces)

- **No invented people and no invented numbers**: a figure is a LIVE server token, a sourced third-party benchmark, or a real named customer. Documented benchmark bands are fine ($4-7/click, $70-250/positive reply, agency $80-200, SDR $50-120, $700 market booked meeting, agency $1,500-5,000/mo, SDR $4,000-7,000/mo); no per-TOOL prices. ## Static-page technical traps

- **Manual `?v=N` on `public/landing/**` CSS/JS**: editing without bumping ships nothing visible to returning visitors/edge. Bump on EVERY html linking it (tokens differ per page). Decide the bump from `git status` at COMMIT time, never plan time (#3938 nearly shipped old CSS with new markup).
- **Each served HTML carries a large inline `<style>` that can beat `css/styles.css` by specificity**: when an edit "doesn't take", grep the page's inline `<style>` for the selector first. Verify a CSS fix by the RENDERED computed value (`getComputedStyle`; iterate `document.styleSheets` + `matches()` to find the winner), never by grepping the stylesheet.
- **JS-injected internal links = SEO orphans**: crawlers/LLM bots parse raw HTML only. Any new statically-served article/cluster page gets a static in-HTML inlink from its hub (and back) in the SAME PR (static `<a class="post-related-card">`; `main.js` fills only EMPTY grids). Verify `curl -sA GPTBot <url> | grep -c 'href="/<slug>"'`.
- **`SITE_NAME` (`src/lib/seo.ts`) REWRITES the served Organization JSON-LD**: `withCanonicalOrganization` deletes any hand-written `Organization` node and injects `organizationJsonLd()` (same object as React `layout.tsx`); also feeds `title.template`. Editing the html `"name"` does nothing; verify off a real `next start`, never source.
- **React landing pages render on a HARDCODED-WHITE body** (`--background: #ffffff`): use plain Tailwind grays (gray-900/600/500, white|gray-50 cards, gray-200 borders), NOT `--dy-*` tokens for content (`layout.tsx` is `data-theme="light"` default now, so dy-themed chrome is coherent; footer stays dark `bg-gray-950`). Verify computed colour with Playwright on PROD after merge.
- **Public apps ship `html { overflow-x: clip }`** (never `hidden`: breaks `position: sticky`); it's a net, fix spills at the element. Wide content scrolls via its own `overflow-x-auto`; decorative `absolute -inset-N` glows stay in-viewport inside `max-w-* mx-auto px-4 sm:px-6 lg:px-8`. `scripts/overflow-audit.mjs [BASE_URL] [--app=landing|sales|docs]` auto-discovers React routes ONLY: static pages (`/pro`, `/agency`, `/how-it-works`...) need explicit routes. Real overflow = body `scrollWidth` > viewport; on mobile contexts the tell is `innerWidth` growing.
- **Fixing an Ahrefs/site audit: target SERVED HTML**, never reconstruct from Next `metadata` (templates compound, metadata inherits). Home: DIS-69 (Ahrefs project 9700515).

## Public rendering: ISR + `unstable_cache`, NEVER Suspense on indexable content

AI scrapers parse raw HTML only (a Suspense fallback = indexed skeleton). Applies to `apps/landing`, `apps/sales-cold-emails-landing`, `apps/docs`.
1. No `<Suspense>` on indexable content (hero, h1/h2, JSON-LD, tables, blog cards, stats); user-specific non-indexable widgets only.
2. Never `force-dynamic` + `revalidate` (force-dynamic wins); prefer `export const revalidate = N` alone.
3. `headers()`/`cookies()` in a page forces dynamic: resolve hostname from `NEXT_PUBLIC_*`.
4. Wrap fetch/DB calls in `unstable_cache` with explicit tags; invalidate with `revalidateTag(tag, "default")` (Next 16.2+ needs the 2nd arg).
5. `unstable_cache` at module top level breaks vitest: mock `next/cache` globally in `tests/setup.ts` (`setupFiles` in `vitest.config.ts`).
6. After any caching change run `scripts/seo-snapshot.sh [BASE_URL]` + `scripts/measure-ttfb.sh`; pre/post in the PR. seo-snapshot does NOT count skeletons: also `curl -sA GPTBot <url> | grep -c animate-pulse` (>0 = data behind Suspense/client fetch).
