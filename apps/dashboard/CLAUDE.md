# apps/dashboard: dashboard-wide rules

Customer dashboard (Next 16, Clerk, React Query v5), a container on the Hetzner box (no Vercel, no preview URLs). Domain rules live in the nested files: `src/components/{onboarding,campaigns,billing,crm,leads,workflows,v2}/CLAUDE.md`. This file: data fetching, cache, reveal, org switching, auth gating, chrome, styling, mobile, gating.

## Verification (dashboard-specific)

- Verify visual/behaviour changes by REPRODUCING: esbuild-bundle the component + compile Tailwind off the app's own `globals.css` + Playwright (1280 and Pixel 7, light and dark). A class grep proves spelling, never paint order, fit, or event order. Playwright specifier is `@playwright/test`; the script must live inside `apps/dashboard`.
- Many tests are source-substring guards: run `pnpm --filter @distribute/dashboard test` before pushing; `tsc` alone misses them.
- Prefer alias-free lib modules (no `@/` runtime import) so they carry REAL unit tests (vitest has no `@` alias). A guard pinning a threaded prop/arg must pin the CALL SITE, not only the component/helper.

## Data fetching: ONE framework (React Query v5, SWR semantics)

- Config in `src/lib/query-provider.tsx`: `staleTime` 60s, `gcTime` 30min, `placeholderData: keepPreviousData` GLOBAL (never per query), `refetchOnWindowFocus/Reconnect`, `retry` 1 (queries) / 0 (mutations). Server components only for the shell.
- Poll: import `pollOptions`/`POLL_INTERVAL` from `src/lib/query-options.ts`, never a local `const pollOptions`. Cadence is 5s (owner: nobody waits more than 5s; features-service view-cache TTL is 5s so polling does not multiply upstream work; read the file before trusting this number). Guard `tests/poll-interval.test.ts`. No slower tier for PAGED reads.
- `installIdleFocusManager` (`lib/idle-focus-manager.ts`, mounted in `query-provider.tsx`) reports unfocused when hidden or idle >2min, which pauses every poll. Load-bearing: AFK polling feeds PostHog rrweb an unbounded mutation stream and OOMs the tab. Never add an always-on poll; keep `refetchIntervalInBackground` default.
- Mutations: `setQueryData(["entity", id], response)` FIRST, then `invalidateQueries(listKey)`; return the invalidation promise.
- **After a write, `await queryClient.refetchQueries(...)`, never `window.location.reload()`.** Reload hands the first frame to the pre-write IndexedDB snapshot, so the removed thing reappears for seconds. Split try/catch at the point of no return so the error copy is true; close the confirm modal AFTER the re-read settles. Reload stays right only for user-initiated recovery (error boundary Try again, stale-build notice). Enumerate every root a write moves; a card removal moves `billingAccount` + `billingPayments`. A reload may also tear down a third-party overlay: re-home that in the provider module (read the vendor's DEPLOYED bundle, e.g. Revolut `instance.destroy()`).
- **A user's own write re-reads EVERY grain the fact lives under**: `lib/write-invalidation.ts` is the one list (`LEAD_OUTCOME_ROOTS`, `CAMPAIGN_MONEY_ROOTS`; `brandSpendableBudget` is the one budget writers forget; `workflowProjection` deliberately absent). The module imports nothing (client taken structurally). Money still lands in ~5s (producer cache); do not recompute in the browser. Budget writers `setQueryData` billing's answer instead of re-reading. Guard `tests/write-invalidation.test.ts`.
- **A control whose only feedback is a spinner reads dead**: hold the pressed statement in local state scoped to the ENTITY it was made on, render it over the served value, drop it on refusal. Producer's answer always wins; not a fallback.
- Mutation button in-flight label stays full opacity (`disabled:opacity-40` only when `!isMutating`) plus a `<Spinner/>`. For a multi-second create-then-navigate, pre-seed the destination query and show a full-screen overlay.
- **Save/dirty gate = LIVE compare against a baseline** (`!formsEqual(form, baseline)`), never a sticky boolean latch.
- **Forms seeded from a query RE-SEED when the payload is a different object** (last-seeded ref, identity not deep-equal). First settled payload is the DISK snapshot, and `setQueryData` is never persisted. A field the user edited and the card they have open outrank the server. Ref impl: `offer-campaigns-card.tsx` / `campaign-controls-modal.tsx` (`seededFrom`).
- Never render `err.message` from `apiCall` (it is the downstream body verbatim): branch on STATUS (+`code`), print own copy, `console.error` the real one. Ref `brand-domain-card.tsx`; guard `tests/brand-domain-card-error.test.ts`. Domain ownership is client-service's `checkout-status`; do not re-derive it.
- A numeric field arriving as string (`"0"`): `z.coerce.number().nullable()`, plus a backend issue.
- A new write to a producer's CLOSED vocabulary: verify with one real prod request before shipping the consumer.
- Never compute a displayed stat in the browser (cost-per-X, totals, shares, ROI, `daily*30`); render the features-service field, or ask for it. Pure formatting is fine. A cost per outcome at zero outcomes is `Learning`, never spend. Every money reader sends `pricing=net` (`tests/projection-pricing-net.test.ts` lists the readers, including server-side `outcome-digest.ts`; the digest alone sends `leads=full`). Never `new ?? old` across two live fields that mean different things (`committedCostUsd` vs `actualCostUsd`); `??` is only for a RENAME.
- Wire-shape rules: deployed openapi is truth (api-registry MCP), safeParse every external reader with per-VERB schemas, a too-narrow `z.object()` strips new fields, additive not-yet-deployed fields are `.optional()`, required-and-nullable fields are `.nullish()` not `.optional()`, a parser shared across grains must accept every grain's body, parse the producer's WHOLE population through the real reader before shipping (a schema from a 2-row sample is a claim about the sample), a field must not be left declared under a renamed producer name. `apps/admin/src/lib/api.ts` has byte-equal readers: migrate both in lockstep.
- A producer verdict (a status token, `lifecycleStatus`, `maturity.isMature`, `rank`, `scopeRank`) is READ, never re-graded from its raw inputs; keep numbers for display/hover. A producer flag that rides a cascade (`measured`) is true at the widest grain: use `resolved.grain`.
- Bulk `?domains=`/`?ids=` readers must chunk (<=200), retry transient transport per chunk, filter junk keys (`isQueryableDomain`), and gate exports on the enrichment settling.
- Free-form passthrough endpoints (`variables`/`inputs`): map keys 1:1 to the template's declared `.variables`.
- When you put a BOUND on a read, grep every consumer of that read and ask what each was COUNTING (a stat row printed the 200 cap as the population). A producer widening what a scope resolves to mis-sizes every consumer (send `view=basic` on brand-sized reads; do not reintroduce parse-then-re-serialize in the gateway).

## Render states and reveal

- **Skeleton rules**: `isPending` (no data) = skeleton; `isFetching && !isPending` = content, silent. NEVER gate terminal UI (not-found, empty state, `isLoading && !data`) on `isLoading`: a query disabled by the org gate reports `isLoading:false` while unresolved, so the empty/not-found state flashes. Use `isPending` (context loading flags too). Only `workflow-detail-panel.tsx` legitimately differs.
- `isPlaceholderData` on a KEY CHANGE = skeleton (keepPreviousData otherwise shows entity A under entity B); prefetch visible entities on open.
- A page fanning one list into N status queries gates each tab on ITS OWN query. Skeleton "while empty and not yet answered" uses `isFetchedAfterMount`, never `isFetching` (flickers on every poll). Guard `tests/audiences-tab-poll-no-flicker.test.ts`.
- **Reveal on SETTLE (`data !== undefined || isError`), never success-only**; one barrier PER visually distinct card; never AND a warm cache with a cold sibling; never gate a barrier on a slow/inline-compute query (card-local skeleton instead); child components trust the page's `pending`, no `pending || !data` re-guard (grep `pending || !` and fix every hit; where a child cannot take an absent payload, render a branch stating the reason). Check each region against the query that FEEDS it. Guard `overview-reveal-on-settle.test.ts`.
- `useCoordinatedReveal(flags)` / `<CoordinatedReveal>` (`lib/use-coordinated-reveal.ts`, children is a render fn): barrier + monotonic latch; a disabled query stays pending forever, so flag it `!enabled || !isPending`; prepend `defsReady` when queries depend on another query; gate a section on its own query, not a context's coarse `loading`. Sidebars: rows gate on `defsReady` alone, count badges on `badgePending`.
- **Static-shell-first**: card frame, title, labels render immediately; only value regions show `<Skeleton/>` (`pending` prop). Skeleton imported into a test-imported component must be a RELATIVE import. Guards `static-shell-reveal.test.ts`.
- No in-page `<Suspense>` for dashboard content. Route-segment `loading.tsx` IS required at org / brand / feature / campaign levels (below the persistent `(dashboard)` layout, never at it); intermediate layouts stay EMPTY server passthroughs (no `cookies()`/`headers()`/fetch). A new route level gets its `loading.tsx`.
- Dynamic routes only prefetch layouts: sidebar `<Link prefetch>`, and drill-down rows that `router.push` warm via `useRoutePrefetch` on `onMouseEnter` AND `onFocus`.
- `useMonotonicStatuses(entries, priority)` (`lib/use-monotonic-status.ts`): every client-polled status-tab surface latches the most-advanced bucket (poll downgrade is a stale read; `console.error` it).
- keep-last-good (`lib/keep-last-good.ts`, `keepLastGoodFields/List`, passed as `structuralSharing`): OPT-IN per query whose nullable fields gate UI and where null = transient; list only those fields; cannot heal the FIRST fetch, so keep a bounded conditional `refetchInterval` (~4s, capped tries) while the payload has no usable data (workflow-projection costs). TanStack types the params `unknown`.
- A full-width row at the top of a list/detail split page goes INSIDE the inner padded content column, never a child of the `flex md:flex-row` root.

## Local-first cache (per-query IndexedDB persister)

- `experimental_createQueryPersister` as a default query option (`query-provider.tsx` + `lib/persist-cache.ts`), IndexedDB via `idb-keyval`. One persister, never a second provider. NOT whole-client persist (localStorage cap + full re-serialize per mutation).
- `PERSISTABLE_QUERY_ROOTS` is an allowlist INVENTORY (default-OFF); `SENSITIVE_QUERY_ROOTS` (`apiKeys`/`byokKeys`/`keySources`) never persisted. A new `useAuthQuery` root MUST be added in the same PR: `tests/persist-query-cache.test.ts` scans the whole key argument and fails otherwise. Deleting a surface leaves roots behind silently: diff the allowlist. Allowlisted only means "may be written", not "was".
- `maxAge` 30 days and `gcTime` 30min are decoupled and finite. `requestPersistentStorage()` at boot is required (else the browser evicts the store); keep it.
- Org-scoped via persister `prefix` = `persisterStorageKey(orgId)`; `storage: undefined` while orgId null or on the server. `buster` = manual `PERSIST_CACHE_VERSION`, never the git SHA; bump on an incompatible shape change AND when a producer adds a field the reader now REQUIRES and a component reads without `?.`.
- Reads are BUCKET-SCOPED and bounded (`lib/idb-bucket.ts` `bucketEntries`, `sweepStaleEntries` at boot, `reclaimLegacyStore` once via `RECLAIM_MARKER_KEY`). Do NOT re-add the mount `restoreQueries` or call `persisterGc()` (both read the whole store). Guard `tests/persist-bucket-scope.test.ts`.
- Nav reseed (`reseedColdQueriesFromDisk`, `coldRestorablePairs`) runs on every org-scoped navigation, decoupled from `enabled`/network, cold-guarded (never stomps fresher memory), buster/org checked; it reads KEYS first (`queryKeyFromStorageKey`, `coldStorageKeys`) and only the surviving values (`valuesForKeys`); the mount read is kicked in the `useState` initializer, not an effect. Backend-down must degrade to STALE.
- `MAX_PERSISTED_ENTRY_BYTES` = 2MB: bigger entries are not written (and are deleted). The cap is a cap on the PAYLOAD you do not own: a producer hydrating rows you never asked for exiles the read from the cache (`/revenue` was 10.9MB vs 43KB of used data, so every money card skeletoned on every load). Fix at the PARSE boundary: keep the question consumers ask (`RevenueOverview.leadOutcomes`, narrowed via `LeadOutcomeSchema = RevenueLeadSchema.pick(...)`; `parseRevenueWithLeads` only for the digest, which sends `?leads=full`; presence of an outcome comes from served `attributedOutcomes`, never inferred from rows). To find it: compare payload sizes of a surface that paints instantly vs one that does not. Raising the cap is never the fix; `gcTime` stays 30min.
- A local-first cache hides a total API outage as a healthy page: the reported broken thing is the one uncached control (export, download). Read the proxy logs and PostHog replay network capture (`rrweb/network@1` in `blob_v2`; the replay holds no DOM text) before probing servers.
- `apiCall` routing: read the SESSION first (per-tab `getTabSessionToken`); the `distribute_anon` hint cookie only breaks the tie when there is no session. `/onboarding/claim` goes through a direct `fetch` to `/api/anon/claim`, not `apiCall`. Guard `anon-routing-session-wins.test.ts` (index compare).
- The `/api/v1/[...path]` proxy MUST stream `res.body`, never `await res.text()` then re-wrap (doubles payload memory; guard `tests/proxy-stream-no-buffer.test.ts` in both apps, so never write that literal in a comment). "API returned a non-JSON response" means the proxy/platform replied non-JSON (container killed/OOM), not that the endpoint is broken: `readJsonResponse` puts status, content-type and a 200-char body preview in the message; read `docker logs distribute-dashboard-app-1` on the box. A failing request that dies too fast is usually the victim of a heavy sibling.

## Org switching: cross-org isolation (DIS-143)

JWT is the sole authority; fail closed; remount on switch; the URL `/orgs/[id]` is the per-tab source of truth.
1. **Server**: `checkProxyOrg` (`lib/proxy-org.ts`) compares `x-active-org-id` (URL org) to `auth().orgId`, 409 `org_desync` on mismatch; call it in every proxy route after the `clerkOrgId` check. Constants in `lib/org-desync.ts`.
2. **Client cache**: inner `QueryClientProvider key={lastResolvedOrgId}` (monotonic: a `useRef` that only stores non-null ids, because Clerk's `organization` blinks null on JWT rotation/focus). Remount replaces `queryClient.clear()`. Keyed on `urlOrgId ?? organization?.id`. No side caches needing a clear (`OrgCacheInvalidator` is deleted).
3. **Source**: `await setActive` THEN `await session?.getToken({ skipCache: true })` before `router.push`, else the stale cookie makes the switch revert itself.
4. **Read gate** `lib/use-auth-query.ts`: `enabled: caller && urlOrg === effectiveActiveOrg`, latched against the null blink (fills only a null; a different non-null org still closes the gate). No `|| !activeOrgId` escape. Any NEW effect calling the API off `useOrganization()` takes `useOrgQueryGate()` too (`UserResolver` does).
5. **Multi-tab**: attach THIS tab's token (`Authorization: Bearer` via `getTabSessionToken()`, a non-hook `window.Clerk.session` read), never the shared cookie. Nothing navigates on an active-org CHANGE (no navigate-on-change effect). Per-tab client surfaces key on the URL org, never `useOrganization()` (only off-/orgs fallbacks; on `?new=1` do NOT show the active org name). Org label = `["orgIdentity", orgId]` snapshot written only when `organization.id === orgId`; brand crumb label from a by-id `getBrand` read, never `find()` in a list cached under another org.
6. **`/onboarding` creates its org**, so it opts out of the org-keyed provider: `<QueryProvider scope="onboarding">` (a layout PROP, never a `usePathname` check) with `orgId={null}`, in-memory cache. Guard `tests/onboarding-org-remount.test.ts`.
7. **Every leg is BOUNDED**: `withTimeout` (`lib/with-timeout.ts`) at `ORG_SWITCH_TIMEOUT_MS` plus `AbortSignal.timeout` on the join fetch; a timeout is loud, not a fallback, and is not a refusal (`isTimeoutError` skips join-and-retry). Never pre-check membership against Clerk's paginated `userMemberships.data` (positive-only for SKIPPING the join); let `setActive` reject and join only then. The 409 retry mints a FRESH token (`getTabSessionToken(forceRefresh)`, backoff `ORG_DESYNC_BACKOFF_MS` 400/900/2000) because a cached token carries the refused org.
- Click answered locally (`tests/org-switch-instant.test.ts`): `setSwitchingOrg` set synchronously BEFORE the first await (carries the NAME); org rows do not go through `go()`, arrival closes the menu; the pending flag clears on ARRIVAL. A failed join/getToken throws (no `.catch(()=>{})` in click handlers), errors stated in the menu. `orgSwitchErrorMessage` (`lib/org-switch-error.ts`): `navigator.onLine === false` is decisive, `true` is never evidence. Several guards pin the handler's literal spellings (`await setActive(...)`, `await session?.getToken(...)`); update spelling, not invariants.
- The god-mode join route (`/api/admin/orgs/:id/join`) is idempotent via Clerk's RESPONSE (`already_a_member_in_organization` = ok), never a paged `getOrganizationMembershipList` pre-check. Staff all-orgs switcher is gated by `isAdminEmail`; the route-level 403 is the sole security boundary in the dashboard (client `isStaff` is cosmetic). Allowlist copies stay byte-equal (dashboard, admin, api-service `src/middleware/auth.ts`).
- `StaleBuildNotice` (`components/stale-build-notice.tsx`, `lib/stale-build.ts`) is the ONE handler for a tab running a replaced bundle (`UnrecognizedActionError`, `ChunkLoadError`, failed dynamic import; listens on `unhandledrejection` AND `error`; narrow match; a NOTICE, never an auto reload; mounted in `(authed)/layout.tsx`).

## Styling and design

- **Reskin centrally** via `app/globals.css` (`html.dark` remap layer; tokens in `:root`), never a per-page sweep. The dashboard has NO theme provider/toggle/script: its `.dark` class is applied by nothing, the remap block is documentation of the mechanism. Served landing ground truth: light, charter blue OKLCH hue 258, Fustat display + DM Mono (read the stylesheet before reskinning). Green accent is DEPRECATED; semantic success green/red stay.

## Mobile

- Dense `<table>` lives in `overflow-x-auto` with a BREAKPOINT-GATED floor (`md:min-w-[720px]` paired with `hidden md:table-cell` columns); an unconditional floor overrides the hidden columns. Add a wide column by moving THAT column's breakpoint, never raising the floor. Free-text column needs `table-fixed md:table-auto` + percentage widths + `min-w-0` to truncate. A folded column reads from ONE binding (computed once, `md:hidden` complements). `CompanyLogo` `size` is a STYLE prop.
- A `grid` needs its base column count (`grid-cols-1 sm:grid-cols-2`); a bare `grid` takes a min-content floor and widens the layout viewport (tell: `window.innerWidth` exceeds the viewport). A line stating WHAT a thing is should wrap, not truncate.
- `min-h-*` never bounds an axis; a PERCENTAGE `max-h-full` against an indefinite parent pins nothing. Onboarding shell uses `max-h-[100svh] overflow-hidden` below `sm:`; short viewports step down via `lib/short-viewport.ts` (siblings own onboarding detail).
- Breadcrumb is visible at all widths (scrolls horizontally, `overflow-visible` while a dropdown is open). The split-panel `absolute inset-0` overlay is the intended mobile drawer. Subagent mobile audits over-report: confirm against the served string.
- Measure fits by RENDERING (scrollWidth vs clientWidth, computed display, old markup beside new), at 360/412.
- A hand-built probe page needs `<meta name="viewport">`; compile CSS through `@tailwindcss/postcss` against `globals.css`; wait for chart/CSS animations before measuring; a page-level component bundle needs next/navigation + next/link stubs, `window.process`, and a `pageerror` listener. Pick a FREE port (`lsof`), `__probe/` is TRACKED (use `__probe-<topic>/`).
