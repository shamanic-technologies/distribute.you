# Dashboard v2 (`src/app/(authed)/v2/**`, `components/v2/`)

Design language, tokens, primitives, recipes, no-gos, render check: load skill `dashboard-v2-ux`. Below is architecture only.

GA since 2026-09-27 for every signed-in user: no allowlist gate, no beta badge (`tests/dashboard-v2.test.ts`). Every page is v2 (Today, Records, Work, Crew, Missions, person, offers + targeting, mission settings, integrations, brand settings, billing, API key, profile, invite).

- **Forks NOTHING in the data layer**: same providers (`QueryProvider`, `OrgContextProvider`, `FeaturesProvider`, `BillingGuardProvider`) and v1 query-key PREFIXES (`["brandRevenue", brandId, ...]`, `useCampaignRows(..., ALL_OFFERS)`). No v2 `api.ts`.
- **ONE offer per dashboard (owner 2026-10-03)**: the sidebar switcher picks an offer under the brand (`SelectedOfferProvider` in `v2-shell.tsx`, `components/v2/selected-offer.tsx`, cookie `distribute-offer-<brandId>` via alias-free `lib/v2/selected-offer.ts`; the URL's offer, or a mission's, wins and is remembered). EVERY brand page reads that offer only: money `getOfferRevenue` / `getOfferDealsValue` / `getOfferContactedValue` (features-service offer grain), leads `useLeadScope` (`brandId`+`offerId`), missions `useMissions` (`allOffers` only for pages addressed by a mission/run id and the offer's own page), runs via the offer's `campaignIds`, daily budget via `splitDailyBudget(..., inScope)`. A brand-wide total appears NOWHERE, on purpose; there is no list of offers (sidebar "Offer" = the selected offer's page; archived offers + Restore sit under it). A new brand read goes through these hooks; guard `tests/v2-selected-offer.test.ts`. Org-level facts (credit, billing, team) stay org-level.
- **A plan hides every daily budget (owner 2026-10-03)**: any surface stating or editing a $/day reads `useDailyBudgetHidden()` (`lib/use-daily-budget-hidden.ts`, true for `payment_mode` `subscription` and until billing answers) and renders nothing budget-shaped; pause/restart stays. Guard `tests/plan-hides-daily-budget.test.ts` lists the surfaces: add yours.
- **Vocabulary**: CREW = one leg x one channel with a proper name (`lib/v2/crews.ts`, alias-free, unlisted pair named by its channel, never invented); MISSION = crew x offer = a campaign identity (no backend); audiences are rows inside a mission. Every channel has a name in `CHANNEL_NAMES`.
- **v1 is DELETED (2026-10-01; git history has it).** No version cookie, no Back to v1. `proxy.ts` redirects EVERY old v1 URL (`/`, `/orgs/**`, `/account`, `/api-keys`) to v2 pre-paint via `v2PathForV1` (`lib/ui-version.ts`, unit-tested): a page with a twin goes to it, anything else to the nearest v2 page above (brand, else org). Old URLs keep arriving (sent emails, Stripe returns, links inside embedded shared components), so never drop a `v2PathForV1` line. Headless side effects (signup/welcome notification, Stripe-return conversions, referral claim) mount in `v2-client-layout.tsx`, the only authed dashboard shell.
- **Forms embed v1 business components** (`setup-pages.tsx`; api-keys/account embed `components/settings/{api-keys-panel,account-profile}.tsx`). Never rewrite a settings form (two editors drift). A v1 component reading `params.id`/`params.offerId` takes an optional prop (`CampaignWorkflowsPage({campaignId})`, `CustomerAudiencesPage({campaignId, offerId})`). Embeds read as v2 through ONE layer: `keel.css` maps v1 utilities under `.v2-root .v2-embed` (`V2Page` wraps bodies; guard `tests/v2-embed-keel-layer.test.ts`); fix a v1 class family there, never per page. LIST pages are v2-native (owner 2026-09-28): Targeting + mission Audiences, Integrations render v2 markup over v1 readers/keys/writes.
- **Billing is v2-native** (`components/v2/billing-page.tsx`) over the SAME `useBillingController` as v1 (`components/billing/use-billing-controller.ts`; a charge path exists once). **The payment mode is a TAG, never a switch** (owner 2026-10-01): each org keeps the mode it has, only staff move it (admin console, billing's staff route); signup flows still set it once through `PUT /v1/accounts/payment_mode`. Owner rule: a control missing a prerequisite the page can supply OFFERS it on click, never a greyed card. **Revolut Business is the default acquirer** (owner 2026-09-29): `declareRevolutDefault()` (`lib/api.ts`, `/api/orgs/revolut`) runs before EVERY card/money call; an org with its card on Stripe stays (`card_elsewhere`). Revolut cannot save a card for $0 (released $1 auth): no "$0" copy. Guards `tests/revolut-default.test.ts`, `v2-billing-page.test.ts`. **Cancelling the plan = `CancelPlanFlow`: one screen per loss (`CANCEL_LOSS_STEPS`: red cross, what stops NOW, what staying keeps; served counts on the first), then reason, offer fitted to it: stay for less from $29 prefilled $99 (a trial is charged now, then confetti), a 1-3 month pause, or write to Kevin; rose confirm; owner 2026-10-03). NO step counter or progress bar (a stepper motivates finishing). A cancel stops ALL sending at once, never at period end.** Keep is primary everywhere, but `Continue to cancel` stays visible on EVERY screen and the reason stays optional: a cancel the customer cannot find breaks online-cancel laws (California, EU, ROSCA) and feeds Stripe disputes. Add screens only if they retain without blocking (`tests/cancel-plan-flow.test.ts`).
