## Model: org > brand > offer > outcome > leg (sales funnel retired 2026-09-25)

`apps/dashboard/src` reads/writes NO sales funnel (`apps/admin` still does). `tests/no-sales-funnel.test.ts` fails on `funnelKey`, retired funnel readers/writers, a `funnel` query param, or the word elsewhere in `src`. It survives only as a producer wire name renamed at ONE parse boundary (`lib/revenue-parse.ts`, `funnelSteps` to `stepWalk`). Public reads: `/v1/public/features/showcase-outcomes` (landing, onboarding), `/v1/public/channel-outcome-economics` (admin model page). Never rebuild a funnel client-side.

- **Vocabulary**: step = node; leg = move between steps (ENTRY leg starts from nothing); channel = feature slug performing legs; outcome = a step one of our channels lands a leg on (customer word; "step" never on screen). "Positive reply" everywhere customers read it (owner 2026-09-24; `hasSalesInterest` in `lib/lead-sales-interest.ts` keeps its name, it is visit OR positive reply).
- `legKey` is OPAQUE, read from features-service `GET /public/channels` via `lib/legs.ts` (`legCatalogueFromWire`, `legFor`, `channelLegs`, `legLabelFor`; hooks `useLegCatalogue`/`useCampaignLeg`), NEVER parsed. Legs no channel performs are hidden.
- **Campaign = (offer x leg x channel)**: rows carry `offerId`, `legKey`, `featureSlug`. Named/marked by leg then channel. `LegMark` (`lib/leg-marks.ts`), `StepMark` (`lib/step-marks.ts`); leg absent from catalogue draws no tile. Landing stops at the offer.
- **A read accepting a leg sends `leg=<legKey>`, else nothing**, never a goal standing in (features-service ranks workflows by what it is asked; a borrowed key returns another outcome's winner). Brand/offer-grain reads send neither (best path, sorted on return). `stepsFor(goal, leg)`/`legSteps`/`leadTabsForLegs` (`lib/goal-steps.ts`) key campaign surfaces; goal is fallback only.
- **Onboarding picks OUTCOMES, launches per pair**: `chainTo`/`pairsForOutcomes` (`lib/start-catalogue.ts`); budget step funds each pair (`campaignBudgets`, `pairBudgetUsd`; underfunded channel total refused); launch calls `saveCampaignBudget` then creates ONE campaign per funded pair with `legKey`+`offerId`. Snapshot backward-compatible (unknown step lands on `outcome`, no version bump); pending blob carries `campaigns` at top level.
- **Brand level has NO goal, only the return.** `salesEconomics.optimizationGoal` is a retired column (defaults `websitePurchase`); never key a brand surface on it nor replace it by PICKING one leg.
