# Onboarding (`components/onboarding/`, `components/start/`, `components/v2/get-started/`, new-org modal)

Rules for the signup/onboarding flows. Fleet-generic lessons live in the global CLAUDE.md and skills.

## ONE flow: `/onboarding`, outcomes in, one funded campaign per (leg x channel) out
- `onboarding.tsx` serves every signup. No `variant` prop, no `isV2`, no beta-gated second flow: a re-added branch is a second money path nobody asked for.
- `/start`, `/onboarding/pay`, `/onboarding/build` are 308s to `/onboarding` (query kept, relative Location). Sell-first screens are `StartPicks` (`components/start/start-picks.tsx`) as steps `welcome | outcome | returns`, in memory, via `StartShell` (owner 2026-09-19: one seamless flow, never a route handoff).
- **Order:** welcome, outcome, returns, url (only without a landing URL), loading, services, audiences, consent, six offer levers, built (recap), account, pricing, bonus, Stripe, celebrate, phone, launching.
- **Outcome screen** offers `startOutcomes`, each with its `StepMark` (`lib/step-marks.ts`). NO channel screen: `DEFAULT_CHANNEL_SLUG` (`lib/start-catalogue.ts`) is ours. ONE form step `form_submitted`; `canonicalStepKey` folds retired `form_filled` / `lead_form_submitted` on READ, never on write.
- **Proof figures are read off the fleet** (`lib/start-proof.ts`, alias-free): strip varies per screen (hot leads, median cost per hot lead, median ROI past the $100 floor), falls back to the founders line, never blank. Named clients = top three by return, random order fixed per mount (`shuffleWithSeed`), only brands `SHOWCASE_PEOPLE` names (consent).
- A producer field whose NAME and documented MEANING differ is rendered by meaning: `minimumCommitmentDays: 30` is time-to-show-results, so nothing reads "30-day commitment" (`NO_COMMITMENT_TAG`). Price reads `From $X per day` (`fromPerDay`). `/start?url=` is READ via `useLandingBrand` (logo.dev mark + host, never a guessed name). `StartShell` resets scroll on every screen (`scrollKey`). A fixed-length list gets a grid sized to it.
- **The anonymous org gets the full $30 welcome credit right away** (owner, 2026-09-29; it was a $5 internal seed before). Nothing is sent before payment.
- **Audience step = ONE textarea "Who do you sell to?"**; nothing searched/suggested/picked/activated in onboarding (owner: audiences built by hand after payment). Prefilled from `suggestBrandIcp`, saved as brand `targetAudience` user-field. brand-service's user-fields vocabulary is a CLOSED set (DB CHECK): verify any new WRITE to a producer's closed vocabulary with one real prod request before shipping. Consequence: new brand has zero audiences, `zero-active` tier fires no reminder modal, banner reads "We are building your audiences" with no CTA. Guard `onboarding-target-audience.test.ts`.
- **Audience prewarm starts BEFORE the lever extraction** in `hydrateOnboardingInBackground` (ICP needs only the services; `curateIcpProfileFields` excludes levers). After it, the step's latch fired its own ICP + suggest and the late prewarm was never adopted (two billed suggests per signup). Guard `onboarding-audience-prewarm-timing.test.ts` (index compare).
- **Retired step names stay in `Step` + `ALL_STEPS`** (`destination`, `objective`, `rates`, `ltr`); removing narrows persisted snapshots and strands mid-checkout sessions. `ONBOARDING_STATE_VERSION` stays 8, `legacyStepFor` maps them; an unknown step parses onto `outcome`. Never bump the version for a new field: make it OPTIONAL on the snapshot.
- **Post-payment needs ride the TOP LEVEL of `PendingCheckoutLaunch`** (Stripe return = fresh page load, React state gone). Campaigns ride as `campaigns: LaunchCampaign[]`, read tolerantly. Bumping the version must never kill an in-flight checkout: `readPendingCheckoutLaunch` reconstructs a minimal current snapshot from top-level fields instead of throwing.
- **Launch names the OFFER, read never created** (`lib/launch-offer.ts` `soleOfferId`, alias-free). Zero or several offers = unattributed (campaign-service/human-service adopt on their tick); read is best-effort, logged loud. The AUDIENCES step cannot name it (may run before the first offer exists): do NOT create an offer from the browser to fix that. Guard `launch-offer.test.ts`.
- Guards: `one-onboarding-flow`, `onboarding-resume-persistence`, `start-picks-surface`, `start-catalogue`, `start-proof`, `step-marks` tests.
