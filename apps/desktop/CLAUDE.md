# apps/desktop (distribute for Mac, private beta)

SwiftUI app, no Electron/Tauri. **The window IS the web dashboard, STRICTLY EXACT** (owner 2026-11-16 « Exact as web », replaces 2026-10-04 « adaptation AI native »; the native sidebar, panels and chat are deleted): `WebShell.swift` shows `dashboard.distribute.you` in a `WKWebView`, Sophie in the Copilot included, so the app cannot drift from the web. Never re-code a dashboard screen natively here: a missing behaviour is something a browser tab does and a bare web view does not (new tab, download, file input, JS confirm), added in `WebShell.swift`. Landing: `distribute.you/desktop` (`apps/landing/src/lib/pages/desktop.ts`), noindex, never linked from the main landing (owner 2026-10-04).

## The one difference with the web: the org's LLM runs on the user's own Claude Code

Owner 2026-11-16: « Ce qui est critique est que le user dépense $0, car tout depuis sa subscription Claude Code. Pas de forfait API. », « chaque client son abonnement », Sophie included.
- **Org-level, by design, no brief or campaign setting**: an org declares it (`PUT /v1/local-llm {enabled}`, from the menu bar switch, the MCP or any AI with the user's key). chat-service then turns every LLM call of that org (completions, judgments, each Sophie round) into a work item, charged $0, usage still measured; a model that is not Claude maps to its tier's Claude model. Contract: chat-service README « Local LLM » (LOCAL-CLAUDE-1116); state in `GET /v1/local-llm` (`runner.connected`, `stillOnPlatform` = the families that cannot run locally).
- **`LocalRunner.swift` is dumb on purpose**: long-poll `POST /v1/local-llm/work/claim`, run the item with `claude -p` exactly as its `claude` field says (`ClaudeCLI.runItem`), `POST .../work/{id}/result`. Every translation lives in chat-service; never add prompt logic here.
- **$0 is enforced here too**: the CLI's environment drops `ANTHROPIC_API_KEY` and the other provider variables, and a run whose init line says `apiKeySource` other than `none` is stopped before its first model call and answered as a failure telling the user to `/login` with their plan. Proven 2026-11-16 (CLI 2.1.80, Max plan): `apiKeySource: none`, structured answer in 4.6 s; Anthropic's help article 15036540 (update 2026-10-07): `claude -p` signed in with a plan draws from the subscription limits.
- **Never a "Login with Claude" / OAuth token in our app** (Anthropic forbids it for third parties without approval): the app never sees a Claude credential, it launches the user's own CLI. A Mac app inherits a bare PATH: `ClaudeCLI.locate()` asks the login shell (`$SHELL -ilc`) for `PATH` and `command -v claude`.
- Each call runs in an empty directory with `--setting-sources project --strict-mcp-config`: without it the user's own `~/.claude/CLAUDE.md` and hooks steer the call (it once answered "MODE: Casual" from the owner's config). The prompt goes on stdin (a chat transcript does not fit an argument).
- **Mac asleep or app quit = the org's calls WAIT, then fail loud** (`local_runner_waiting`); chat-service never falls back to a paid key. The runner lives with the menu bar item, so closing the window does not stop it.
- **Which orgs it serves**: the ones `GET /v1/local-llm/orgs` lists, read every 30 s: every org the user is a MEMBER of that declared it, wherever it was declared (menu, dashboard, MCP in Conductor). Membership, never staff reach (api-service LOCAL-CLAUDE-ORGS-1116): a staff Mac never runs a customer's calls on the staff member's own subscription; to run a client's org from your Mac, be a member of that org. The menu shows a switch per org up to 25 orgs, above that only the declared ones.

## Sign-in
One sign-in, inside the window, with the dashboard's own screens (the web view sends a Safari user agent: Google refuses its sign-in to an embedded view's default one). With no stored key the window opens `/desktop/connect?port=&state=` (`apps/dashboard/src/lib/desktop-connect.ts`, unchanged): the page mints a user key named "distribute for Mac" and navigates to `http://127.0.0.1:<port>/callback?state=&key=`. Nothing listens there: `WebShell` catches that navigation, cancels it, accepts the key only with OUR state, stores it in `~/Library/Application Support/Distribute/api-key`, mode 600 (`KeyStore.swift`; owner 2026-11-16: no longer the login Keychain, whose item is tied to the ad-hoc signature, so every update asked for the Mac password before the runner could start; a key from an older build is moved over once). Menu bar › Sign out clears the key and the web session.

## Build and ship
- **Built by CI only** (`.github/workflows/desktop.yml`, `macos-15` runner with Xcode; GitHub retired `macos-14`, the run was cancelled with zero steps, 2026-11-16): `scripts/build-app.sh` = `swiftc` per arch + `lipo` (universal), hand-written `Info.plist`, ad-hoc `codesign`, `ditto` zip. No `Package.swift`: the local Command Line Tools have a broken SwiftPM manifest link and an SDK/compiler mismatch; a push to a branch is the compile check (download with `gh run download <id> -n Distribute`). No snapshot step any more: the look is the web's.
- Plain classes, no `@MainActor` annotations: `@Published` state is mutated inside `await MainActor.run`; a variable shared with a timer or a detached task is a `let` or a small class box, never a captured `var`.
- **RAM is a feature** (owner 2026-10-15: the app runs beside many Claude sessions): one web view, small `URLCache`, each `claude` call capped at 512 MB heap, one call at a time per org, all stopped on quit.
- Every push to `main` touching `apps/desktop` re-uploads `Distribute.zip` to the `desktop-latest` pre-release (never marked Latest); the landing's button and `distribute.you/desktop/install.sh` point there.
- Not notarized (no Apple Developer ID): `install.sh` installs via curl (no quarantine flag) and clears `com.apple.quarantine`; the browser download needs System Settings, Privacy and Security, Open Anyway.
